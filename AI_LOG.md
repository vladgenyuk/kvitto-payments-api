# Работа с ИИ

Ассистент: OpenAI Codex, семейство GPT-6. ИИ использовался для реализации,
рефакторинга, анализа граничных случаев и подготовки проверок.
Инструменты проверки: pytest/httpx, Ruff, coverage, Docker Compose и GitHub Actions.
Скриншоты API получены через Playwright; отчёт подготовлен с помощью ReportLab.

## Ключевые задачи и контекст

Ниже приведена смысловая редакция запросов с сохранением их задачи и контекста.

1. **Реализация по спецификации.** «Реализуй API платежей по приложенному ТЗ:
   тарифы, промокод, рассрочка, идемпотентность и переходы статусов.
   Подготовь проект и проверь соответствие требованиям».
   Контекст: исходный PDF с контрактом API, бизнес-правилами и критериями оценки.
2. **ООП-структура.** «Переработай проект в ООП-стиле по примеру backend из
   указанного репозитория и ветки».
   Контекст: `u-bro/Backend`, ветка `dev`, каталог `Backend-Bot-master/app/backend`.
   Структура адаптирована под задачи сервиса; расчёты и API определяются исходным ТЗ.
3. **Аудит и подготовка к сдаче.** «Проверь код по ТЗ, исправь замечания,
   запусти проект и тесты через Docker Compose. Подготовь минимальный комплект
   документации и примеры работы API».
   Контекст: текущий код, исходная спецификация и результаты предыдущих проверок.

## Ревью предложений ИИ

Проверка граничных значений выявила два случая ответа 500: идентификатор за
пределами int64 и число `1e9999` в ошибке валидации. Добавлены ограничение диапазона
и безопасная сериализация неконечных значений с сохранением формата ошибки 422.
Оба случая покрыты регрессионными тестами.

Первоначальный тест параллельных запросов не гарантировал конфликт записи.
Он усилен async-барьером: проверяются реальная коллизия UNIQUE, одна запись в БД
и одинаковый результат повторных запросов.

## Проверка результата

В Docker проходят 121 тест, Ruff и проверка форматирования; покрытие кода - 99%.
Отдельная HTTP-проверка подтверждает работу собранного приложения, включая HMAC.
GitHub Actions повторяет проверки при push и pull request.
